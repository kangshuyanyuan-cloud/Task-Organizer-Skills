作業の終わりに、今回の内容を記録に残す。
次に作業を始めるとき（`work-start`）に「どこまで進んで、何が残っているか」がすぐ分かるようにするためのスキル。

## 先に読むもの

このスキルを置いた `.claude` フォルダの `shared/前提.md`（このファイルから見て `../../shared/前提.md`）。
記録の置き場所・Gitの使い方は、すべてここの値を使う。

## 手順

### 1. 日付と時刻を確かめる

```bash
date +%Y-%m-%d
date +%H:%M
```

会話の中の日付ではなく、パソコンの時刻を使う。

### 2. 今回の作業をまとめる

この作業で実際にやったこと（作ったファイル・直したもの・実行したこと・決まったこと・終わっていないこと）を、短い箇条書きにする。専門用語は使いすぎない。

### 3. 記録を書く

**(1) 作業ログ**：`作業ログ/<YYYY-MM-DD>.md`

- フォルダが無ければ作る
- ファイルが**無ければ**、`# 作業ログ <YYYY-MM-DD>` の見出しから書く
- ファイルが**あれば**、末尾に `## <HH:MM> セッション` から下だけを足す（前の内容は消さない。`# 作業ログ` の見出しは足さない）

```markdown
## <HH:MM> セッション
**やったこと**
- ...

**決まったこと**
- ...

**次にやること / 終わっていないこと**
- ...
```

形は `shared/見本/作業ログ/YYYY-MM-DD.md` と同じにする。

**(2) ステータスファイル**

- 無ければ `shared/見本/STATUS.md` の形で新しく作る
- 進行中の作業の「状態」と「次にやること」を最新にする（終わったものは `済` にするか表から外し、新しく残ったものは足す）
- 状態は `やることリストの型.md` と同じ4つ（`未` / `進行中` / `済` / `待ち（相手の名前）`）で書く
- つまずいた点・次に同じ失敗をしないための注意があれば足す（前の項目は消さない）
- 大事な決定があれば、日付・決定・理由を1行で残す

**(3) やることリスト**

- 今日のやることリストがあれば、今回終わった行の「状態」を `済` に直す
- 次の `work-start` は、このリストの `済` 以外の行を繰り越す。ここで直し忘れると、終わった作業がまた出てくる

### 4. Gitに記録する

`前提.md` で「Gitを使うか」が「使わない」なら、このステップは飛ばす。

**(1) まず状態を見る**

```bash
git status -sb
```

- いまのブランチが `前提.md` の作業ブランチと**違う**なら、ここで止めて報告する（ブランチは勝手に切り替えない）
- 記録のファイル以外の変更が混ざっていても、それには触らない（含めない・消さない・退避しない）

**(2) 記録のファイルだけをコミットする**

記録のファイル（ステータスファイル・今日の作業ログ・やることリストのフォルダ）のうち、**実際にあるものだけ**を並べる。
無いものを並べると、コマンド全体が失敗する。

```bash
git add -- STATUS.md 作業ログ/<YYYY-MM-DD>.md やることリスト/
git commit -m "docs: 作業ログ <YYYY-MM-DD>" -- STATUS.md 作業ログ/<YYYY-MM-DD>.md やることリスト/
```

- 置き場所は `前提.md` の値に合わせる
- `--` のあとに場所を書くと、**そこに書いたファイルだけ**がコミットされる（前から `git add` してあったほかの変更は入らない）
- 差分が無くてコミットされなかった場合は、その旨だけ伝える

**(3) 共有先に送る**（`前提.md` で「記録をpushするか」が「する」のときだけ）

`git remote` で何も出なければ（共有先が無ければ）飛ばす。

```bash
git status --porcelain --untracked-files=no   # 記録以外に、まだ記録していない変更が残っていないか
```

- 新しく作っただけでGitに入れていないファイルは、取り込みの邪魔にならないので数えない（`--untracked-files=no`）
- **何か出たら、ここで止めて報告する**（取り込みの途中でほかの変更とぶつかるのを避けるため。ほかの変更は退避も破棄もしない）。記録のコミットは手元に残っているので、次の作業終わりで一緒に送れる
- 何も出なければ、次へ進む

```bash
git fetch
git log --oneline HEAD..@{u}           # 他の人の新しい変更が無いか、送る前に見る
git pull --rebase                      # あれば先に取り込む
git push
```

- `@{u}` は「いまのブランチが追いかけている共有先のブランチ」のこと。設定が無いと失敗するので、そのときは `origin/<作業ブランチ>` に読み替える
- 取り込みで同じファイルがぶつかった（コンフリクト）ら、どちらかを勝手に捨てず、ここで止めて報告する
- 送るのが認証などで失敗したら、エラー内容をそのまま伝える（認証の設定は触らない）

### 5. 完了の報告

- 作成・追記したファイルの場所
- コミットの番号（短いもの）と、送ったかどうか
- 他の人の変更を取り込んだ場合は、その内容
- 記録に含めなかった変更があれば、その一覧
- 次にやること（作業ログに書いたもの）

## 守ること

- 作業ログは箇条書き中心で、あとから読んで分かる言葉で書く
- 記録は消さずに足していく
