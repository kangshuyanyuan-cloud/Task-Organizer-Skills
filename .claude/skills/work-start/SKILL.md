作業を始めるときに、**いきなり手を動かさない**。
これまでの記録を読み直して「今日やること」を表にまとめ、**確認を取ってから**作業に入る。
前回どこまで進んだか・何が残っているか・他の人が何を変えたかを、最初に整理するためのスキル。

## 前提（自分の環境に合わせて書き換える）

| 項目 | 例 | 説明 |
|---|---|---|
| ステータスファイル | `STATUS.md` | 進行中の作業と「次にやること」を書いておくファイル |
| 作業ログの置き場所 | `作業ログ/` | `work-end` が `YYYY-MM-DD.md` で書き出す場所 |
| やることリストの置き場所 | `やることリスト/` | このスキルが出したリストの保存先 |
| 新着を見るフォルダ | `inbox/` | 資料や文字起こしを置くフォルダ（無ければ省略） |
| 状態を見るGitリポジトリ | `.`（いまのフォルダ） | 複数あれば並べる。Gitを使っていなければ省略 |

表の形・優先順位のつけ方は `.claude/shared/やることリストの型.md` に書いてある。**先に読む。**

## 手順

### 1. 記録を読む

| 読むもの | 何を取るか |
|---|---|
| ステータスファイル | 進行中の作業と「次にやること」 |
| 作業ログの最新2本 | 前回やったこと、途中で止まったこと、つまずいた点 |
| 前回のやることリスト | 状態が `済` 以外の行を**そのまま今日に繰り越す**（消さない） |
| 新着を見るフォルダ（7日以内） | 文字起こしがあれば `meeting-todo` の手順に入る |

ファイル名だけで判断せず、**中身を開いて読む**。

### 2. Gitの状態を確認する

チームで同じリポジトリを触っていると、自分がいない間に他の人が変更を足していることがある。
それを知らずに今日の予定を立てないよう、最初に確認する。

```bash
git fetch                              # リモートの最新を取ってくる（手元のファイルは変わらない）
git status -sb                         # いまのブランチと、未コミットの変更
git log --oneline HEAD..origin/main    # 他の人の新しいコミット（手元にまだ無いもの）
git log --oneline origin/main..HEAD    # 自分の未pushのコミット
```

見つかったものは、やることリストの材料にする。

| 見つかったもの | リストでの扱い |
|---|---|
| 他の人の新しいコミット | 「変更を取り込む（`git pull`）」を上のほうに入れる。`git log -p HEAD..origin/main` で中身を読み、今日触るファイルと重なるならかんたん説明に書く |
| 自分の未pushのコミット | 「前回の分をpushする」を入れる |
| 未コミットの変更 | 中身を見て、前回の途中作業なら繰り越しに入れる。何の変更か分からないものは「確認したいこと」に回す（勝手に消さない・コミットしない） |
| fetch が失敗した | 「他の人の変更は未確認」と表の下に書く |

この時点では `git pull` しない。取り込みは、確認が取れたあとのタスクとして行う。

### 3. 今日やることを組み立てる

- 繰り越し分＋記録から読み取った宿題＋新着からの依頼＋Gitの状態 を、ひとつの表にまとめる
- **期限が過ぎているものは先頭に置き、「期限切れ」と書く**
- 相手の返事待ちのものは「待ち（相手の名前）」にする
- 1日で終わる量を超えていたら、**今日やる分と今日はやらない分を線で分ける**

### 4. 表を出して、確認を取る

`.claude/shared/やることリストの型.md` の「表の形」「確認したいことは、最初にまとめて出す」
「出したあとの動き」に従う。

- 表 → 進め方と完了条件 → 確認したいこと → 仮に決めたこと の順で出す
- やることリストの置き場所に `やることリスト_<YYYY-MM-DD>.md` で保存する（同じ日は追記）
- **確認が取れるまで実作業をしない**

### 5. 確認が取れたら

- ファイル先頭を `状態：確認済み（HH:MM）` に書き換える
- 上から順に進め、1件終わるごとに「状態」列を更新する
- 作業の終わりは `work-end` で記録を残す

## 守ること

- 表と箇条書きで整理する
- 記録に無いことを推測で書かない。分からないことは「確認したいこと」に回す
- 「コードに無い＝やらない」とは限らない。これから作る予定のものもあるので、記録で確かめる
